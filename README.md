# FreexOfficial DeepSeek Chat — минимальный публичный модуль

**Статус: Прототип, проверено локально.** Отдельный, изолированный модуль — не главная страница FreexOfficial, не пульт управления. Цель: проверить подключение нового AI-агента к одному простому чату.

**Папка переименована** 2026-07-17: было `Claude/deepseek-chat-public/`, стало `Claude/Публичный репозиторий/` — это единственная папка Claude, которая является отдельным git-репозиторием (`origin` → `github.com/creatorfreex/FreexOficial`), содержимое которой предназначено для публикации. Остальные файлы Claude сюда не попадают.

## Что реализовано
- `index.html` / `styles.css` / `js/app.js` — интерфейс: статус подключения, история сообщений, ввод, кнопка «Новый чат», настройки, выбор модели. `app.js` намеренно в подпапке `js/`, не в корне (см. «Публикация» ниже — причина).
- `server.cjs` — локальный сервер-прокси (порт **8768**). Единственная задача: держать реальный API-ключ на сервере, чтобы он не попадал в браузер/HTML/JS. Расширение `.cjs` (не `.js`) — намеренно: `package.json` объявляет `"type": "module"` для `api/*.js`, а этот файл написан в CommonJS (`require`), без `.cjs` Node отказывается его запускать.
- Модели: **`deepseek-v4-flash`** (по умолчанию) и **`deepseek-v4-pro`** — актуальные названия, проверено по официальной документации DeepSeek 2026-07-17 (`api-docs.deepseek.com`). Старые `deepseek-chat`/`deepseek-reasoner` официально отключаются 24.07.2026 15:59 UTC — сознательно не использованы.
- Обработка ошибок: 401 / 402 / 429 / 500 / 503 — отдельные понятные сообщения на русском (`app.js`, `errorMessageFor()`).

## Ключ — где и как
Приоритет на сервере: **ключ из этой вкладки браузера** (введён в ⚙ Настройках, хранится только в JS-переменной `inMemoryKey`, не в localStorage/sessionStorage, исчезает при перезагрузке) → иначе **`Искусственный интеллект/SECRETS/deepseek.key`** (общее хранилище проекта, решение руководителя от 2026-07-17). Ключ никогда не возвращается клиенту и не попадает в исходный код страницы — проверено: `curl` к `/api/chat` без ключа и с тестовым фейковым ключом (401 от настоящего api.deepseek.com, не сетевая ошибка) — оба раза сервер не отдал ключ обратно.

## Как запустить локально
```
cd "Искусственный интеллект/Claude/Публичный репозиторий"
node server.cjs
```
Открыть `http://127.0.0.1:8768/`.

## Публикация — задеплоено на Vercel Создателем

`api/chat.js` + `api/health.js` + `vercel.json` — тот же паттерн, что уже работает в проде у исходного проекта FreeX (`Искусственный интеллект/Архив/freex/freex/api/chat.js`, задеплоен на `freex-eta.vercel.app`): статика + serverless-функция, ключ только через переменную окружения `DEEPSEEK_API_KEY` на стороне Vercel, никогда в коде.

**Важно: этот git-репозиторий — не подпапка внутри монорепо FreexOfficial.** Он создан отдельно, `git init` был сделан прямо в этой папке, поэтому на GitHub `index.html`/`app.js`/`api/` и т.д. лежат **в корне репозитория**. Путь вида `Искусственный интеллект/Claude/Публичный репозиторий` внутри самого репозитория **не существует** — если где-то в настройках Vercel указан такой Root Directory, это ошибка (Claude сам её один раз дал по ошибке, см. ниже).

**Хронология публикации (2026-07-17):**
1. GitHub-токен получил право `Contents: Read and write` → `git push` прошёл (`09b80db`), код реально на `github.com/creatorfreex/FreexOficial`.
2. Создатель подключил GitHub App Vercel и импортировал проект.
3. Деплой падал: `500 FUNCTION_INVOCATION_FAILED`. Причина №1 — не было `package.json` с `"type": "module"`, а `api/chat.js`/`api/health.js` используют `export default` (ESM) → исправлено (`11feae3`).
4. Продолжал падать. Причина №2 — `server.js` (CommonJS, `require`) конфликтовал с новым `"type": "module"` и ломал сборку Vercel целиком → исключён через `.vercelignore` (`4ab1e33`).
5. Всё ещё падал. Причина №3, главная — лог Vercel показал `Using app.js as the root entrypoint`: `.js`-файл прямо в корне репозитория (рядом с `index.html`) распознавался как серверный вход и Vercel пытался исполнить браузерный скрипт как Node-функцию. Исправлено переносом `app.js` → `js/app.js` (как сделано у оригинального FreeX) — так в корне не остаётся ни одного «лишнего» `.js`, кроме `server.cjs` (тоже переименован из `.js`, тем же приёмом, что и с причиной №2, но теперь и для локального запуска — `"type":"module"` в package.json ломал `require()` в самом `server.js`, не только на Vercel).

GitHub Pages как альтернатива не подходит в принципе для этого модуля — только статика, `api/chat.js` там не выполнится.

## Что НЕ сделано (честно)
- Публичный URL Vercel после последнего фикса (перенос `app.js`) — не проверен Claude вживую, ждёт подтверждения от Создателя.
- PR / CodeRabbit-ревью — не использовались, весь код шёл прямым push в `main`.
- Проверка с телефона / по мобильной сети — не делалась.
- Реальный тест с настоящим ключом DeepSeek на проде — не делался (хотя локально с реальным `DEEPSEEK_API_KEY` из окружения — ответ настоящий, проверено).
